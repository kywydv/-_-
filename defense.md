# Підготовка до захисту

## Що робить проєкт
Проєкт реалізує інструментарій для SIPL. Спочатку лексер перетворює текст програми на токени
та фіксує їхні позиції. Парсер перевіряє структуру відповідно до граматики й будує власне
типізоване AST. Інтерпретатор обходить AST, змінює стан змінних і створює trace-події.

## Основні поняття
- **БНФ** — спосіб формального опису синтаксису через нетермінали та правила.
- **AST** — абстрактне синтаксичне дерево, яке зберігає структуру програми без зайвих деталей тексту.
- **SourceSpan** — позиція вузла у вихідному тексті: рядок і колонка початку та кінця.
- **Стан** — відображення імен змінних у цілі значення.
- **Інтерпретатор** — компонент, який безпосередньо виконує AST.
- **Trace** — послідовність подій виконання, потрібна для аналізу та налагодження.

## Як пояснити архітектуру
1. На вході маємо текст SIPL-файлу.
2. Лексер розпізнає ключові слова, ідентифікатори, числа й оператори.
3. Парсер будує AST та повідомляє синтаксичні помилки з координатами.
4. Інтерпретатор виконує вузли AST над словником стану.
5. Trace записує початок/кінець оператора, перевірку умов і зміну змінних.
6. CLI надає команди для перевірки, виконання та отримання JSON.

## Демонстрація
```sipl
begin
    P := 1;
    while N > 0 do
    begin
        P := P * N;
        N := N - 1
    end
end
```
Запуск:
```bash
sipl run examples/power.sipl --state '{"X":2,"Y":5}'
```
Для цієї програми очікується `R = 32`, якщо використати файл `power.sipl` з початковим станом `X=2`, `Y=5`.
